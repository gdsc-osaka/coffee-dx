# 次枠キュー・シフト管理 設計書

## 概要

ドリップ係向け画面と、次にセットするバッチを決めるアルゴリズムの設計方針。

### 基本方針

- **効率と公平性の両立**: 古い注文（特に古い 2〜3 注文）を後回しにしない公平性を担保しつつ、ドリッパーのバッチ処理による効率化を両立する
- **役割の特化**: ドリップ係画面は「現在抽出中のもの」を除外し、**「次に 3 台のドリッパーへセットすべき予定（次枠バッチ群）」の確認と準備に特化**させる
- **既存資産の活用**: 不足杯数（未抽出の注文）を計算するロジックや抽出開始のトリガーは、他機能・既存コードと連携する

---

## 前提（物理仕様とデータ構造）

- **管理対象**: 抽出中のコーヒーは別で管理しているため、**「次のドリッパー枠（最大 3 台分の次期バッチ群）」のみ**をキューとして管理する
- **バッチの単位**: 1 バッチ = 1 台のドリッパーで抽出する「1 種類 × 最大 3 杯」の塊。これが最大 3 つ並ぶ

---

## 画面構成（シフト補充型・次枠キュー方式）

### 表示内容

次にセットする予定のバッチ群（最大 3 台分）を表示する。

### 挙動（シフト & リフィル）

```
1. 別画面などで「抽出開始」の操作がなされると、次枠キューの先頭にあったバッチが消費される。
2. キュー全体が 1 つずつ前にシフトする。
3. 空いた末尾に、新しい未処理注文から計算されたバッチを補充する。
```

表示を総入れ替えするのではなく、**完了・開始に合わせて 1 つずつスライドして補充していく**ため、現場の担当者が状況を追いやすく混乱しない。

---

## アルゴリズム設計（次枠の計算・補充ロジック）

| 観点 | 方針 |
|------|------|
| 入力情報 | 「不足バッチ」の計算結果や、DB の未処理注文リストを参照する |
| 公平性の担保（古い注文の優先） | 注文の古い順（特に古い 2〜3 注文）を優先的にキューの前方に組み込み、極端な待ち時間を防ぐ |
| 効率的なバッチ割り当て（3 台への振り分け） | 抽出開始などでキューが 1 つ消費・シフトした際、残りの未処理注文から同じ種類の注文をまとめて「最大 3 杯」の塊（バッチ）を動的に再計算し、キューの末尾を補充する |
